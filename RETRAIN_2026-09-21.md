### A pre-existing bug fixed as a side effect

The May `cysteine-classifications.tsv` carried **probabilities that disagreed with its own
classifications** — e.g. `p_dis = 0.9784` on a row whose `evidence_tags` read `esm2_dis:0.999`.
`dump-tsv.sql` explains why: an earlier version read `esm2_predictions_held_out_v1`, "an earlier
inference whose probabilities disagreed with the classifications", dropped in migration 005. The
SQL was corrected but **the TSV was never regenerated**, so the download page served inconsistent
probabilities for four months. The new file has `p_*` equal to `evidence_tags` on every row.

## Two things deliberately not changed

**`scripts/migrations/003_esm2_runs.sql`** still writes `{"disulfide": 0.742, "metal_binding":
0.972}`. That is correct: the migration created run 1, which genuinely had those thresholds.
Migrations are a historical record and must not be rewritten. Run 2 was inserted separately.

**The `FIG_3D` constant and the live `fig3d_subcellular.csv` differ by ~0.2 pp** (nucleus 0.176 vs
0.1737). The constant is the paper snapshot; the CSV is the live query with the site's own domain
scoping. `paperData.ts` already documents this split for `FIG_3B` ("Fig3BPanel renders live
percentages directly on the bars"), so the divergence is by design rather than an error — but it is
worth knowing before someone tries to make them agree.
